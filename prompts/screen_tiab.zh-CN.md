# 题摘层逐批判定 prompt（模板 · 中文）

> **用法**：把 `{{...}}` 全部替换成本项目实际值，把这份文件存进工作目录（例如
> `<workdir>/prompts/screen_tiab.md`），之后每次调用**只给「prompt 文件路径 + 批次号」**，
> 不要每次重新内联全文——口径漂移和父上下文膨胀都来自内联（见 `docs/PIPELINE.md`）。
>
> **配套**：`pipeline/protocol.json` 是词表与编码的**权威定义**，本模板里的词表要跟它一致；
> 中央校验器是 `pipeline/s2_validate.py`，**执行方不得自建校验脚本**。

---

## 占位符清单

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{{PROJECT_NAME}}` | 综述题目 | 暴露 X 与结局 Y |
| `{{RUBRIC_PATH}}` | 判据文件绝对路径（含 PECO、纳入标准、排除编码表） | `…/screening/SCREENING_RUBRIC.md` |
| `{{BATCH_DIR}}` | 批次目录绝对路径 | `…/<workdir>/batches` |
| `{{DECISION_DIR}}` | 判定输出目录绝对路径 | `…/<workdir>/decisions` |
| `{{BATCH}}` | 批号（调用时给） | `b_001` |
| `{{N}}` | 本批条数（见批次文件 `n` 字段） | `250` |
| `{{CODE_TABLE}}` | 编码 → 含义对照表（由 `protocol.json` 的 `code_meanings` 生成） | 见下 |
| `{{VOCAB_FORM}}` `{{VOCAB_EXP}}` `{{VOCAB_OUT}}` `{{VOCAB_NEED}}` | 受控词表（由 `protocol.json` 的 `vocabularies` 生成） | 见下 |
| `{{DOMAIN_LADDER}}` | **领域判据阶梯**（本项目科学部分，可整体替换） | 见下方示例块 |
| `{{FAST_LANE_CODE}}` | 快速通道编码 | `X4` |
| `{{PREFIX}}` | 批次文件名前缀 | `b_` |

## 模板正文（复制以下内容）

```text
你是 {{PROJECT_NAME}} 系统综述的题摘初筛执行方，熟悉该领域的观察性研究设计与 Meta 分析。
只依据下面给定的文件工作：不联网、不查库、不使用外部知识或记忆补充信息。

【本阶段定位】本阶段**不做最终纳入决定**。你只把每条记录分成三类：
   · Exclude  —— 有明确排除理由，直接排除；
   · Hold     —— 题摘里没有排除理由、且与 PECO 相关，但关键信息缺失，留待全文；
   · Review   —— 无新数据的文献（综述/社论/信件…），排除但保留作引文追溯。
   **题摘阶段永远不产出 Include**（全文核验后才可能 Include）。

【STEP 1｜读判据（必读，完整读完再判）】
{{RUBRIC_PATH}}
它包含本项目协议（PECO、纳入/排除标准、结局口径）。

【STEP 2｜读本批记录（n 见文件内 "n" 字段）】
{{BATCH_DIR}}\{{BATCH}}.json
结构：{"batch":"{{BATCH}}","n":{{N}},"records":[{"i":<int>,"y":<年>,"j":<刊>,"t":<题名>,"a":<摘要，可能为空串>}, ...]}

【STEP 3｜逐条判定：严格按下列优先顺序，命中即停】

{{DOMAIN_LADDER}}

【初筛不得输出的编码】有些编码只有在全文才能确认（例如"与已纳入研究同一队列、随访完全重叠"）。
这类编码**不在初筛词表内**，一律不得输出。

【硬口径（本阶段最易判错的点）】
  · 结局口径：{{OUTCOME_DEFINITION}}
  · 拿不准「有没有排除理由」时 → 选 **Hold**，不要用 X 赌。**宁可错留，不可错杀。**

【无摘要记录】
 只按题名走同一优先顺序；
  题名足以定论就照判；题名不足以定论 → **Hold**，并在理由里注明「仅题名判定」，
  need 里写清全文必须查什么。

【STEP 4｜输出：严格 JSON，写入】
{{DECISION_DIR}}\{{BATCH}}.decisions.json

{"batch":"{{BATCH}}","n":{{N}},"decisions":[ ... ]}

字段按 d 分三种形态 —— **不多写、不少写**：

(a) 快速通道（d={{FAST_LANE_CODE 的族}} 且 c={{FAST_LANE_CODE}}，只给 4 个字段）
    {"i":15,"d":"X","c":"{{FAST_LANE_CODE}}","r":"一句话理由"}
(b) 其余排除族，或无新数据族
    {"i":23,"d":"X","c":"X3","form":"prognostic","exp":"<暴露词>",
     "out":"<结局词>","r":"理由","s":"原文证据片段","conf":"high"}
(c) Hold 族（平台记 Maybe）
    {"i":41,"d":"F","c":"F2","form":"cohort","exp":"<暴露词>","out":"<结局词>",
     "need":["outcome","effect"],"r":"理由","s":"原文片段","eff":"","conf":"medium"}

字段规则
  · c 必须与其 d 同族：{{FAMILY_MAP}}
  · form（文献/研究形态）：{{VOCAB_FORM}}
     —— form 与 d **互相独立**：form 只看**体裁/设计**；
        d 看**有无新数据、内容是否命中判据**（letter 里若报告了原始数据 → 不得判 R1）。
  · exp（暴露类型）：{{VOCAB_EXP}}
  · out（结局类型）：{{VOCAB_OUT}}
  · need（**仅 Hold 族必填**）：数组，取值只能来自 {{VOCAB_NEED}}；至少 1 个；
    写明"全文里必须查到什么才能定纳入"。
  · r 必填（≤140 字符）；s ≤120 字符，无则空串。
  · eff：仅当摘要**字面写出**效应量（OR/RR/HR/SIR/SMR/IRR 及 95%CI）时**原样抄录**，否则空串。
         —— **严禁编造、推算、补全任何数字。**
  · conf：high / medium / low（信息不足一律 low）。

【STEP 5｜完成前自检（必须全部通过，否则改到通过再结束）】
  · len(decisions) == 本批 n；i 集合与本批输入完全一致：不增、不减、不重、不漏
  · 每个 c 与 d 同族
  · 三种形态的字段严格对应，不多不少
  · need 里每个值都在词表内、且至少 1 个

只回一行：{{BATCH}} done: n=xx, Exclude=xx Review=xx Hold=xx, validated
```

## `{{DOMAIN_LADDER}}` 示例块（结构示范）

> **这一块是本模板里唯一必须按项目重写的部分。** 下面这份结构示范保留在此作为写法参考：
> **每个编码都要给出触发条件、反例和边界**，否则执行方会把兜底编码当成垃圾桶。
> 注意它通篇只用「暴露 / 目标结局 / 多部位」这类抽象措辞，不出现具体疾病名——
> 判据属于研究方案的范畴，写进 prompt 时只需与 `protocol.json` 保持一致。

```text
 1. R1 **无新数据**的文献 → d=R
    范围：综述 / Meta 分析 / 社论 / 评论 / 致编辑信 / 指南 / 研究方案 / 勘误
    ⚠️ 判定依据是"有没有原始数据"，不是"文献体裁"：
       一篇 letter / comment 若报告了原始数据（新队列、新病例、新效应量）→ 不得判 R1，
       从第 2 步起按内容判 d，但 form 仍写 letter / comment。
 2. X4 设计性排除 → d=X
    · 病例报告 → X4（form=case-report）   · 病例系列 n<10 → X4（form=case-series）
    · 动物实验 → X4（form=animal）        · 体外/细胞/机制实验 → X4（form=in-vitro）
    · 病例系列 n≥10 且无对照 → 不判 X4，走第 9 步 X5
 3. M1 MR / GWAS / 基因关联研究，且结局涉目标结局或多部位癌 → d=M（Hold 池）
    ⚠️ 必须在第 4 步之前识别：MR 题摘常常不出现暴露词，先走分岔会被 F6/X9 截走。
 4. 暴露-结局分岔
    · 题摘有暴露措辞 → 进第 5 步
    · 无暴露措辞、有目标结局措辞：
        - 多因素/危险因素型 → F6
        - 只锁定某个与暴露无关的单一因素 → X9
        - 看不出来 → F6（保守）
    · 既无暴露措辞、也无目标结局措辞 → X1
    · ⚠️ 有些词是"暴露相邻词"，命中即按"有暴露"处理，不得判 X1。
 5. F1  暴露 + 明确目标结局                                    → d=F
 6. F2  暴露队列 + 结局为多部位/泛癌（all cancers / any cancer / multiple sites /
       site-specific cancers / second primary …）                → d=F
       ⚠️ 收紧："其他癌症"只有表示**并列多个部位**时才算 F2；
          若结局其实只是**单一非目标癌种** → 走第 8 步 X2；
          读不出部位数量 → 保守判 F2，并在理由里写"部位数不明"。
 7. F5  仅"合并口径"、看不出能否拆出目标结局                    → d=F
 8. X2  有暴露，但结局是明确单一非目标癌种且无多部位措辞         → d=X
 9. X5  横断面 / 无比较组（含 n≥10 无对照病例系列）/ 无时间顺序  → d=X
10. X3  无癌症发生结局（技术、影像、诊断、治疗、预后、并发症、机制）→ d=X
11. F3  **Hold（严格三条件，缺一不可）** → d=F
     (a) 不满足 X1–X5、X9 任何一条（题摘里找不到明确排除理由）；
     (b) 题摘里至少有 PECO 正向信号；
     (c) 关键信息缺失，无法确认是否符合 PECO —— 必须在 need 写明缺什么。
    ⚠️ 反例（这些不是 F3，必须按对应编码排除，不许偷懒塞 F3）：
       · 在目标结局患者中做预后/生存/诊疗分析   → X3
       · 描述性发病趋势、无比较组               → X5
       · n≥10 且无对照的病例系列                → X5
       · 唯一癌结局是非目标癌种                 → X2
       · 只在患者里回顾既往暴露史（无时间顺序） → X5
       · 题摘既无暴露词、也无任何肿瘤结局词     → X1
```

## 为什么模板长这样（改动前先读）

1. **批次文件只带题名+摘要**，不带期刊/作者/PMID：执行方看得到的信息越少，越不容易
   用"这个期刊应该不相关"之类的旁证偷懒。
2. **三种输出形态 + 条件式字段**是刻意的：最常见的失败模式是执行方给每条记录都填满
   所有字段，字段一多就开始编。快速通道省 token，`need` 让 Hold 池可执行。
3. **`eff` 只准字面抄录**：编造一个效应量比留空危险得多，因为它会一路混进数据提取表。
4. **"宁可错留"是明写的**：题摘阶段的目标是零漏检，不是省全文工作量。
5. **一行回执**：父代理不需要读每批的细节，细节在文件里。长汇报纯烧父上下文。
